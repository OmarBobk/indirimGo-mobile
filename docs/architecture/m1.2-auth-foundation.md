## Decision

The app uses a small feature-first Flutter structure. Core infrastructure is
shared only where M1.2 needs it, while authentication owns its models,
repository, state, and screens. Manual immutable models validate every required
OpenAPI field and ignore unknown additive fields.

Laravel remains authoritative for credentials, account status, customer role,
2FA, token expiry, validation, and every domain or financial decision.

## Runtime flow

1. `main.dart` validates `API_BASE_URL` and injects configuration and secure
   storage.
2. Riverpod starts in `initializing`; no login screen is shown yet.
3. The repository reads secure storage and calls `/me` when a token exists.
4. Success enters the shell. An authoritative rejection clears the token and
   enters login. Offline/timeout/5xx keeps the token and shows retry.
5. Login either stores the returned bearer token or holds the 202 challenge in
   memory.
6. Authenticator or recovery completion exchanges that challenge for a token.
7. Confirmed logout revokes the current token and clears local storage.

`go_router` redirects solely from authentication state. Direct shell access,
direct 2FA access without a challenge, stale login access, and startup redirect
loops are prevented.

## Security boundaries

- Secure storage contains only the Sanctum token and returned expiry metadata.
- Username, password, authenticator code, recovery code, and challenge token
  are never persisted.
- The Dio client has no logging interceptor and does not retry auth requests.
- Exception string output excludes server messages and request/response data.
- 401 clears storage. `/me` or logout 403 is also treated as an authoritative
  rejected session by the repository.
- Network and server failures do not destroy the token.
- No refresh-token behavior exists.
- Android debug alone permits cleartext local HTTP. Main/release explicitly
  denies arbitrary cleartext.
- No client-side trusted pricing or financial mutation exists.

## Dependencies

| Dependency | M1.2 justification |
| --- | --- |
| `flutter_riverpod` | Explicit, testable authentication and locale state without generators |
| `go_router` | Authentication-aware route protection and redirect handling |
| `dio` | Configured JSON client, interceptors, status/error/header mapping |
| `flutter_secure_storage` | Android platform-protected Sanctum token storage |
| `flutter_localizations` | Official Flutter localization delegates |
| `intl` | Flutter-pinned localization runtime used by generated ARB code |
| `flutter_lints` | Supported static-analysis baseline |
| Flutter test SDK | Unit, widget, and router verification |

No mocking, code-generation, analytics, notification, Firebase, biometric, or
unrelated UI dependency is included.

## UI direction

The interface uses an assertive yellow-and-black wordmark treatment, generous
spacing, strong typography, and neutral surfaces rather than an unapproved
navigation system. Arabic is the fallback and renders RTL; English is supported.
Light/dark themes, semantic status updates, touch targets, focus actions, and
large-text layouts are included. No trustworthy official mobile logo was
present in the Laravel tracked assets, so no logo was copied or redrawn.

## Scope exclusions

The authenticated shell proves identity and logout only. Catalog, categories,
search, cart, checkout, wallet, top-ups, orders, fulfillments, refunds, Customer
Activity, notifications, and future navigation architecture remain outside
M1.2.
