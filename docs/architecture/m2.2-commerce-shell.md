## Decision

Authenticated customers browse the Laravel catalog through a focused Flutter
feature module. Riverpod controllers call a single `CatalogRepository` over the
existing Dio client. Manual immutable models match OpenAPI exactly. Flutter
never recalculates prices, never invents purchase CTAs, and never caches
personalized catalog responses offline.

## Screens and routes

| Route | Screen |
| --- | --- |
| `/app` | Catalog Home |
| `/app/packages` | Package list/search (`category_id`, `q` query params) |
| `/app/packages/:id` | Package detail (numeric id) |
| `/app/account` | Account + logout (existing auth behavior) |

`go_router` allows any `/app…` location while authenticated and redirects all
other phases to startup/login/2FA. Nested catalog routes avoid redirect loops
during session restoration and logout.

## State and data flow

1. Auth restore succeeds → Home controller loads `GET catalog/home`.
2. Search/browse → Package list controller loads `GET packages` with exact
   query params. Search trims input, ignores 1-character queries, debounces
   ~400 ms, cancels superseded requests.
3. Package cards navigate by numeric id → Detail controller loads
   `GET packages/{id}`.
4. `catalogCustomerIdProvider` tracks the authenticated user id. Logout or
   customer switch cancels in-flight work and clears personalized state so a
   stale response cannot overwrite a newer session.

## Money invariants

- Preserve `Money.amount` as a string (`^-?\d+\.\d{2}$`).
- Never parse amount into `double` or multiply/discount/convert/round.
- Customer-facing text uses only `display.formatted`.
- `meta.prices_visible=false` → localized “price hidden”; money fields null.
- Individual null money with prices visible → localized “price unavailable”.
- Custom options never receive an amount input or client quote in M2.2.

## Image behavior

- Use `Image.network` with loading/error builders.
- Null or unsafe URLs soft-null to a local icon placeholder.
- Do not rewrite hosts/paths; do not add `cached_network_image`.

## Offline limitations

M2.2 does **not** claim offline browsing. Network/timeout/5xx keep the Sanctum
session and show retry UI. Failed load-more/refresh preserves already loaded
content. There is no persistent catalog disk cache.

## Testing

Fixture-driven model tests, Dio repository tests (headers, query params, 401
clearing, 404/`package_not_found`, 422 field scrubbing, cancel), controller
tests (debounce, stale search, load-more, customer switch), and widget/router
tests (RTL/LTR, auth protection, shelves, detail modes, accessibility keys).
All use fakes — no live Laravel required.

## Scope exclusions

Cart, buy now, checkout, wallet, orders, fulfillments, refunds, notifications,
Activity UI, product requirements, custom-amount input/quotation, realtime
catalog, push, registration, password reset, deep links, recommendations,
client pricing/FX, bottom navigation, Firebase, analytics, biometrics, and new
codegen packages.

## Local development

```powershell
php artisan serve --host=0.0.0.0 --port=8000
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

Laravel `APP_URL` must be correct so package `image_url` values resolve.

Physical Android device (preferred secure loopback approach):

```powershell
adb reverse tcp:8000 tcp:8000
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
```

Do not broaden Android cleartext to arbitrary LAN hosts. Do not create `.env`.
