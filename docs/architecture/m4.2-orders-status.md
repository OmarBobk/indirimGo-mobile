# M4.2 Order History and Fulfillment Status

## Contract and routes

Laravel `origin/staging` is authoritative. Later mobile slices consume Mobile
API 1.4.0 search/filter query parameters documented in
[`m4.5.2-ux-foundation.md`](m4.5.2-ux-foundation.md). This M4.2 note remains
the source for list/detail parsing, polling, and recovery rules:

- `GET /orders?page={page}&per_page=20` (M4.2; `q` and `customer_state` added in 1.4.0)
- `GET /orders/{order_number}` using the existing `CheckoutSuccess` wrapper
- `/app/orders` for paginated owned history
- `/app/orders/:orderNumber` for owned detail and receipt reopening

The existing auth redirect protects both routes. A missing, malformed, or
cross-customer order receives the same safe localized not-found experience.

## List and detail state

`features/orders` contains manual immutable models, a focused repository,
customer-scoped Riverpod controllers, localized status mapping, and screens.
The list retains safe in-memory data during refresh/network/server failures,
deduplicates `order_number` while appending pages, and never persists response
bodies. Detail refresh likewise retains its last safe receipt.

Money uses the shared `Money` model. Decimal `amount` values stay strings and
display uses Laravel-provided formatting. Flutter does not calculate totals,
payment truth, fulfillment truth, or affordability.

## Polling lifecycle

Detail performs an initial request and, only for `pending`, `queued`, or
`processing` **fulfillment** status, schedules up to eight non-overlapping
polls at five-second intervals. Polling also requires the app to be in the
foreground, Orders to be the selected indexed-stack branch, and that
order-detail route to be visible. Each next poll is scheduled only after the
prior request finishes. Terminal fulfillment states stop polling.

Disposal, app backgrounding, logout, and customer changes cancel timers and Dio
tokens and advance an operation epoch. A delayed response is accepted only when
both its epoch and customer id still match. Offline, timeout, rate-limit, and
server failures preserve authentication and the last safe detail. Manual
refresh remains available after the bounded cycle.

## Customer isolation and receipt recovery

Order state exists only in memory and is cleared as soon as authentication is
not fully authenticated or the customer id changes. The coordinated auth
controller remains the only session-ending boundary for authoritative 401 and
allowlisted 403 responses.

Checkout success and startup recovery continue to navigate to the detail route.
Navigation and history reads never create, change, or clear a pending-checkout
record. Done/Home clears a completed recovery anchor only when that anchor
matches the displayed order. Opening and leaving an older historical receipt
does not affect a newer anchor.

## Localization and accessibility

All payment, fulfillment, and customer-state allowlisted values map to Arabic
and English ARB copy. Status is always represented by text. Arabic layout is
RTL while money, currency codes, and `ORD-…` identifiers are explicitly LTR.
Order cards expose one semantic label, controls retain minimum touch targets,
loading/refresh/error states use live-region semantics, and layouts scroll for
large text.

## Exclusions

M4.2 did not add search or filters; those arrived in M4.5.2. This slice still
adds no refund/retry/cancel action, cart, wallet top-up, push notification,
Reverb subscription, persistent order cache, Laravel change, production
configuration, or deployment.

Omar’s M4.3 local walkthrough of this order-history slice passed after backend
`#48` and mobile `#7` merged. See
[`m4.5.2-ux-foundation.md`](m4.5.2-ux-foundation.md) for later UX work, which
is not claimed as accepted yet.

## Local M4.3 run

Run the Laravel `staging` checkout locally with its migrations, then:

```powershell
flutter pub get --enforce-lockfile
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

For a physical Android device, use `adb reverse tcp:8000 tcp:8000` and
`http://127.0.0.1:8000/api/v1`. These HTTP origins are debug-only; profile and
release builds still require HTTPS. Do not put credentials or real environment
URLs in source or `.env` files.
