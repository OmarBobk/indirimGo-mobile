# M4.5.2 App-wide UX Foundation

This note covers navigation, language preference, Orders API 1.4.0 search and
filters, status badges, and catalog media frames. It does not change Laravel,
production assets, Wallet top-up, refund/retry/cancel, push, or Reverb.

## Navigation and Android back

Authenticated destinations use `StatefulShellRoute.indexedStack` with four
branch navigators:

| Destination | Location | Branch |
| --- | --- | --- |
| Home | `/app` | 0 |
| Packages | `/app/packages` | 1 |
| Orders | `/app/orders` | 2 |
| Account | `/app/account` | 3 |

Package detail stays on the Packages branch. Order detail stays on the Orders
branch. Re-tapping the selected destination calls `goBranch` with
`initialLocation: true` so that branch returns to its root. Each branch keeps
its scroll position, search/filter fields, and safe in-memory data while
hidden.

Navigation chrome is a labeled Material 3 `NavigationBar`, or a `NavigationRail`
when the shell is at least 840 logical pixels wide. Chrome is hidden on login,
2FA, buy, checkout review, and checkout recovery. Checkout review and recovery
remain top-level routes outside the shell so existing `PopScope` submit and
recovery protection is unchanged.

Android back pops the active branch’s inner route first. At a non-Home branch
root it returns to Home. At Home root it uses normal Android exit behavior.

Logout and customer id changes pop every branch to its first route and clear
customer-scoped controllers.

## Language preference

The Login, 2FA, and Account screens share one selector: Device language,
العربية, and English. The only persisted value is the non-secret preference
`locale.preference = system | ar | en`, stored with `SharedPreferencesWithCache`
(`allowList` limited to that key). Tokens and checkout recovery stay in secure
storage.

`system` uses the existing supported-locale resolver (Arabic fallback) and
follows device locale changes. Explicit `ar` / `en` ignore later device
changes. Preference read failures fall back to a usable system default. The
preference survives restart, logout, and session expiration.

`MaterialApp` locale, text direction, dates, validation copy, dialogs, and
navigation labels update immediately. The current route, form input,
authentication, and checkout/recovery state must remain. `apiClientProvider`
does not watch locale; each request reads `Accept-Language` from a resolver so
Dio is not reconstructed and in-flight checkout is not cancelled. Catalog
names, descriptions, and historical item names stay exactly as Laravel
returned. Money and `ORD-…` values stay LTR inside Arabic layouts. There is no
Laravel locale endpoint.

## Orders API 1.4.0

List requests are `GET /orders?page=…&per_page=20` with optional `q` and
`customer_state`. Empty `q` is omitted. Typed search is trimmed, clamped to
100 characters, debounced 400ms, and submitted immediately from the IME search
action without a duplicate in-flight request. One character shows guidance and
does not send a request. Combined search and filter always reset to page 1,
cancel the previous list request, and ignore delayed responses from an older
query.

Filter chips send only `needs_attention`, `in_progress`, `delivered`, or
`refunded`. `all` and `other` are never sent. The chips wrap so Arabic labels
and large text remain on-screen instead of sitting in a fixed-height strip.
Empty history and “no matches” are distinct. Pull-to-refresh, explicit Load
more, deduplication, and retained data on same-query refresh failure are
unchanged. Customer-state badges reuse the server `customer_state` values;
Payment and Fulfillment stay separately labeled on detail.

Order polling still follows unfinished `fulfillment_status` (`pending`,
`queued`, `processing`), not `payment_status` or `customer_state`. Because
indexed-stack branches stay mounted while hidden, polling also requires the
app to be in the foreground, Orders to be the selected branch, and that
order-detail route to be the visible location. Switching tabs, covering the
route, backgrounding, logout, or customer switch cancel the timer and Dio
token.

Receipt **Done** acknowledges only a matching completed recovery anchor, then
goes to Orders. The explicit Home action acknowledges only a matching anchor,
then goes Home. Ordinary navigation, back, tab selection, successful receipt
loading, and opening a historical order never clear another order’s anchor.

## Catalog images

`CatalogMediaFrame` paints square slots with `BoxFit.contain`, a muted
placeholder, and an error fallback. Decode size is logical size ×
`devicePixelRatio` via `ResizeImage` with `ResizeImagePolicy.fit` so small
source assets are not upscaled. The same provider identity is used for a small
visible Home prefetch (at most eight unique URLs) and for painting, so Home ↔
Packages can reuse the in-memory image cache. Package detail uses
aspect-ratio-constrained contain, not cover cropping.

Decode sizing reduces decode/memory cost. It does not shrink downloaded file
bytes. This slice does not add a disk-cache package: there was no measured
repeated-download evidence in this environment that justified persisting
image bytes. HTTP cache headers are not treated as proof of Flutter caching.
Private JSON, prices, tokens, and customer data are never stored as part of
image handling. Laravel, image contracts, CDN configuration, and production
assets are unchanged.

## Local acceptance walkthrough

1. Sign in. Confirm Home, Packages, Orders, and Account destinations.
2. Open a package, switch to Orders, return to Packages: the detail (or list
   search) is still there. Re-tap Packages to return to the list root.
3. Open an unfinished order, switch to Home, confirm status polling stops,
   then return and use manual refresh.
4. Change language on Login, 2FA, and Account. Confirm RTL/LTR, nav labels,
   and that typed input / the current route remain.
5. Search Orders by order number and item name (2+ characters), try one
   character, then each status filter. Confirm empty history vs no matches.
6. Confirm Home/Packages cards keep logos contained and aligned with names,
   with LTR prices.

Do not put credentials or real environment URLs in source or `--dart-define`
beyond the documented local debug hosts.
